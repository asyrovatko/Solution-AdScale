## AdScale — Архитектура AS-IS

### Цель бизнеса

Трансформировать систему AdScale, которая работает уже несколько лет и находится на пределе возможностей, 
чтобы она выдержала рост нагрузки после подключения интеграции с крупной DSP-площадкой (Demand-Side Platform) и 
была подготовлена к последующему развитию

### Область применения

***Система AdScale*** - SaaS-платформа для размещения цифровой рекламы

### Глоссарий предметной области

| **Победитель**                           | Кандидат, ставка которого наиболее соответствует бизнес-правилам                                                                                                            |
| **Победная ставка**                      | Ставка, которую сделал победитель                                                                                                                                           |
| **Контракт**                             | Договорённость о показе: кто (рекламодатель), что (подготовленная реклама) и по какой цене (ставка) показывает и выполнение каких условий по действиям пользователя ожидает |
| **OpenRTB**                              | Стандартный протокол, по которому DSP взаимодействует с SSP. Также используется для взаимодействия с системой AdScale                                                       |
| **Bid request / bid response**           | Запрос и ответ по OpenRTB                                                                                                                                                   |

| **Правило бюджета**                      | Условие, изменяющее ставку, если текущее состояние бюжета кампании соотвествует ограничению по показателям бюджета                                                          |
| **Поправка ставки (multiplier)**         | Изменение ставки при выполнении конкретного правила                                                                                                                         |
| **Рекламный контент**                    | Картинка, видео или текст, который настраивает рекламодатель и видит пользователь                                                                                           |
| **Бюджет**                               | Лимит денег на кампанию                                                                                                                                                     |
| **Резерв бюджета**                       | Деньги, временно замороженные под конкретный аукцион                                                                                                                        |
| **Агрегаты бюджета**                     | Показатели расхода бюджета                                                                                                                                                  |
| **Сегмент аудитории**                    | Группа пользователей с общими интересами                                                                                                                                    |
| **Агрегаты таргетинга по пользователю**  | Накопленная информация о пользователе на основе его действий и данных                                                                                                       |
| **Аргрегаты таргетинга по кампании**     | Накопленная информация о кампании, на основе действий пользователей с рекламами этой камапнии                                                                               |
| **CPM (Cost Per Mille)**                 | Плата за 1000 показов                                                                                                                                                       |
| **CPC (Cost Per Click)**                 | Плата за клик                                                                                                                                                               |
| **CPA (Cost Per Action)**                | Плата за действие: покупку, подписку и т. п.                                                                                                                                |
| **CTR (Click-Through Rate)**             | Процент кликов от показов: если показали 1000 раз, кликнули 20 — CTR = 2 %                                                                                                  |
| **Платежный шлюз**                       | Внешняя система, посредством которой рекламодатель пополняет бюджет                                                                                                         |
| **Денежная операция (transaction)**      | Идемпотентный  фактического движения денег: пополнение, списание, возврат                                                                                                   |
| **Счет (account)**                       | Подтверждение системы AdScale о списание средств с бюджета рекламной кампании в результате выполнения условия контракта по действиям пользователя                           |
| **Списание (debit)**                     | Заявка на уменьшение бюджета в результате выполнения контракта                                                                                                              |

| **Сотрудник AdScale**                    | Сотрудники, обеспечивающие интересы владельца продукта и работу системы AdScale                                                                                             |

## Бизнес-контекст и цели

### Бизнес-функции

* Рекламодатель
  * регистрируется и авторизуется в системе AdScale с помощью учетных данных рекламодателя
  * управляет 
    * рекламной кампанией, 
    * стратегиями ставок (правилами таргетинга, правилами бюджета) 
    * рекламным контентом
  * пополняет бюджет и настраивает его для рекламных кампаний
  * запрашивает и просматривает отчеты и показатели
  * получает счета
  * просматривает историю операций
* DSP-партнёр
  * авторизуется в системе AdScale с помощью учетных данных партнёра
  * отправляет запрос на рекламу для пользователя сайта/приложения
  * направляет сформированную рекламу пользователю сайта/приложения
  * оправляет информацию о применении рекламы
* Пользователь сайта/приложения
  * совершает действие с рекламой (просматривает, кликает и др.)
* Система AdScale
  * обрабатывает запрос о рекламе
  * подбирает кандидатов на аукцион из рекламных кампаний рекламодателей
  * рассчитывает ставки рекламных кампаний на основе стратегий ставок
  * запускает аукцион в реальном времени по ставкам кандидатов, из которых по бизнес-правилам выбирается победитель
  * формирует рекламу по контенту победителя
  * сохраняет действия с рекламой, которые совершил пользователь сайта/приложения
  * списывает оплату за действия пользователя с бюджета рекламодателя
  * обеспечивает пополнение средств на бюджет
  * предоставляется счета по списаниям
  * рассчитывает показатели рекламных кампаний
  * формирует отчеты запрошенные рекламодателем
* Платежная система
  * Осуществляет средств на бюджет
* Владелец продукта
  * Управляет бизнес-правилами аукциона
  * Получает списанные средства от рекламодателя
* Сотрудник AdScale
  * Администрирует учетныe данныe рекламодателя
  * Администрирует учетные данные партнёра
  * Отслеживает работоспособность всех компонент системы
  * Обеспечивает поддержку всех компонент системы AdScale
  * Разрабатывает все компоненты системы AdScale
  * Развертывает все компоненты системы AdScale

### Бизнес-цели

* Подключить нового крупного DSP-партнера
* Обеспечить работоспособность системы при росте нагрузки
  * Промежуточное решение должно выдержать рост нагрузки на 20%
  * Целевое решение должно выдержать рост нагрузки на 100% и должно быть подготовлено к дальнейшему росту
* Гарантировать стабильное время отклика и исключить сбои и простои системы от запроса рекламы до действия пользователя с рекламой
* Трансформация системы должна быть произведена без остановки бизнеса

#### Промежуточное решение

* Требования:
  * подключить новую DSP-площадки без деградации SLA
  * удержать текущих клиентов и поддерживать трафик не менее 18 000 RPS
  * строго гарантировать, что время отклика не превысит 100ms (предусмотрены штрафы за деградацию времени отклика (latency))
  * гарантировать отсутствие сбоев сервиса ставок (предусмотрены штрафы за простои (downtime))
  * обеспечить непрерывность бизнеса (требуется постепенная миграция)
  * обеспечить масштабирование наиболее нагруженных компонентов
  * обеспечить разделение критичных и некритичных потоков
* Ограничения
  * Срок — три месяца
  * Бюджет ограничен

#### Целевое решение

* Требования:
  * SLA 99,9%
  * Поддерживать трафик 50 000 RPS
  * время отклика не превысит 80ms
  * Микросервисная архитектура
  * Обеспечить событийно-ориентированную обработку
  * Обеспечить мультиплатформенную интеграцию
  * Обеспечить горизонтальное масштабирование
  * Обеспечить мультирегиональное развертывание
* Ограничения
  * Срок - год

#### Риски

* Репутационные потери и потеря клиента из-за невозможности обслужить клиента в результате сбоя движка ставок
* Штрафы в результате за деградации времени отклика (latency) и простоев (downtime)

## Описание текущей ИТ-инфраструктуры

### Обзор

#### Технологический стек

* Архитектура: гибридный монолит на нескольких языках (С++ / Go / Python / Node.js)
* База данных: одна PostgreSQL (одна инстанция, все модули работают с общей схемой)
* Кеширование: Отсутствие кеширования (каждый запрос идёт напрямую в базу данных)
* Очереди: Нет очередей (все операции синхронные, так что при пиковой нагрузке потоки блокируются)
* Контейнеризация: Нет
* Деплой: Вручную
* Инфраструктура: Один production-кластер

#### Нагрузочный профиль

* Время отклика: P95 latency уже на уровне 110-120 ms (150ms при нагрузке) от запроса рекламы до ее показа при рекомендуемом не более 100ms и целевом не более 80ms
* Трафик: Система уже показывает признаки периодической деградации на 15 000 RPS в пике, а требуется 18000 RPS
* Запас производительности: отсутствует
* Конкурирующие потоки к базе данных
* Высокая нагрузка на запись (события кликов и показов)
* Постоянный поток событий (event stream)
