# Потоковая обработка событий

В решение используются **два** механизма асинхронной передачи, и они не заменяют друг друга:

|  Механизм        |  Для чего                                                                 |  Гарантия     | Повторы                                  |
|------------------|---------------------------------------------------------------------------|---------------|------------------------------------------|
| **Apache Kafka** | События: изменения кампаний, действия пользователей, бюджетов, таргетинга | at-least-once | Перечитывание из топика                  |
| **RabbitMQ**     | Задачи: платежи, операции, формирование отчётов                           | ACK/NACK      | Requeue с backoff, после N попыток - DLQ |

## События Kafka

| Событие                | Кто публикует              | Кто читает                                                       | Что означает                                         |
|------------------------|----------------------------|------------------------------------------------------------------|------------------------------------------------------|
| `campaign_changed`     | Campaign BL [1.C.5]        | BFF [5.2], Update Cache Worker [5.1], Analytics Worker [1.A.a.1] | Кампания создана или изменена                        |
| `content_changed`      | Campaign BL [1.C.5]        | Update Cache Worker [5.1], Analytics Worker [1.A.a.1]            | Рекламный контент изменён                            |
| `strategy_changed`     | Campaign BL [1.C.5]        | Update Cache Worker [5.1], Analytics Worker [1.A.a.1]            | Стратегия ставки изменена                            |
| `state_budget_changed` | Financial BL [4.F.6.3]     | BFF [5.2], Update Cache Worker [5.1], Analytics Worker [1.A.a.1] | Состояние бюджета изменилось                         |
| `targeting_changed`    | Statistics BL [3.S.4]      | Update Cache Worker [5.1.2], Analytics Worker [1.A.a.1]          | Агрегаты таргетинга обновились                       |
| `analytics_changed`    | Analytics Worker [1.A.a.3] | BFF [5.2]                                                        | Показатели аналитики пересчитаны                     |
| `action_endUser`       | Delivery API [3.D.4]       | Statistics Worker [3.S.1.1], Analytics Worker [1.A.a.1]          | Пользователь совершил действие с рекламой            |
| `contract_create`      | Ad Server [2.R.5.1]        | Contract Worker [3.F.1], Analytics Worker [1.A.a.1]              | Контракт сформирован                                 |
| `contract_activate`    | Delivery API [3.D.4(b)]    | Contract Worker [3.F.1]                                          | Показ подтверждён (выигрыш)                          |
| `contract_deactivate`  | Delivery API [3.D.4(a)]    | Contract Worker [3.F.1], Analytics Worker [1.A.a.1]              | Показ не состоялся (проигрыш)                        |
| `contract_completed`   | Stats Worker [3.S.4.1]     | Contract Worker [3.F.1], Analytics Worker [1.A.a.1]              | Условие контракта выполнено                          |
| `transaction`          | Financial BL [4.F.6.3]     | Analytics Worker [1.A.a.1]                                       | Выполняется операция по деньгам                      |
| `bid_cache_init`       | Ad API [2.R.2.3(a)]        | Update Cache Worker                                              | В кэше ставок не было кампаний - нужна инициализация |

**Порядок и ключи.** События одного объекта должны идти по порядку, поэтому ключом выбирается ID этого объекта: `campaign_id` для изменений кампаний, `account_id` для денег. Так события одной кампании попадают в одну партицию и не перемешиваются.
**Повторная обработка.** Событие может прийти дважды (гарантия at-least-once). Поэтому потребители либо сравнивают версию (как кэш ставок), либо используют уникальный ключ (как идемпотентные транзакции).

## Связка Producer → топик → Consumer (действие)

| Producer                 | Событие                                                   | Consumer                 | Что делает с событием                                              |
|--------------------------|-----------------------------------------------------------|--------------------------|--------------------------------------------------------------------|
| Campaign Business Logic  | `campaign_changed`, `content_changed`, `strategy_changed` | Advertiser Dashboard BFF | Обновляет кэш кабинета (кампании)                                  |
|                          |                                                           | Update Cache Worker      | Обновляет кэш ставок, при необходимости забирает баннер у Delivery |
|                          |                                                           | Analytics Worker         | Пишет событие в ClickHouse для отчётов                             |
| Financial Business Logic | `state_budget_changed`                                    | Advertiser Dashboard BFF | Обновляет кэш кабинета (бюджеты)                                   |
|                          |                                                           | Update Cache Worker      | Обновляет состояние бюджета в кэше ставок                          |
| Analytics Worker         | `analytics_changed`                                       | Advertiser Dashboard BFF | Обновляет агрегаты и пересобирает dashboard                        |
| Delivery API             | `action_endUser`                                          | Stats Worker             | Накапливает батч действий и обновляет таргетинг                    |
|                          |                                                           | Analytics Worker         | Пишет событие в ClickHouse                                         |
| Delivery API             | `contract_activate`, `contract_deactivate`                | Contract Worker          | Обновляет контракт, удаляет или создаёт резерв                     |
| Ad Server                | `contract_create`                                         | Contract Worker          | Создаёт контракт и резерв бюджета                                  |
| Statistics BL            | `targeting_changed`                                       | Update Cache Worker      | Обновляет агрегаты таргетинга в кэше ставок                        |
| Stats Worker             | `contract_completed`                                      | Contract Worker          | Закрывает контракт, создаёт списание                               |
|                          |                                                           | Analytics Worker         | Пишет событие в отчёты                                             |
| Financial BL             | `transaction`                                             | Analytics Worker         | Пишет операцию в отчёты                                            |
| Ad API                   | `bid_cache_init`                                          | Update Cache Worker      | Инициализирует кэш ставок с нуля                                   |

**Ключевой принцип.** Одно событие читают несколько сервисов независимо: Kafka хранит его на диске, поэтому каждый читает в своём темпе и не мешает остальным. Добавление нового потребителя не требует изменений у остальных.

## Задачи RabbitMQ

| Очередь               | Кто ставит              | Кто обрабатывает           | Что делает                                       | При ошибке                                          |
|-----------------------|-------------------------|----------------------------|--------------------------------------------------|-----------------------------------------------------|
| **credit**            | Financial API [4.F.1.2] | Credit Worker [4.F.2]      | Создаёт пополнение и идёт в платёжный шлюз       | NACK + DLQ после 3 попыток, иначе requeue с backoff |
| **credit (callback)** | Financial API [4.F.4.2] | Credit Worker [4.F.5]      | Обновляет пополнение по ответу шлюза             | Удаляет пополнение, повтор с backoff                |
| **transaction**       | Credit Worker [4.F.5.3] | Transaction Worker [4.F.6] | Проводит операцию: бюджет, счёт, агрегаты        | Saga-компенсация, NACK + DLQ после 3 попыток        |
| **report**            | Analytics API [1.A.3]   | Reports Worker [1.A.4]     | Строит отчёт из ClickHouse и сохраняет результат | NACK + DLQ после 3 попыток, иначе requeue с backoff |

## Политика хранения

| Данные               | Где                    | Срок                         | Почему                                      |
|----------------------|------------------------|------------------------------|---------------------------------------------|
| События платформы    | Kafka                  | 7 дней                       | Запас на переобработку и сверку за неделю   |
| События и агрегаты   | ClickHouse (Analytics) | по регламенту платформы      | Разбор инцидентов, отчёты, обучение моделей |
| Действия с рекламой  | ClickHouse (Stats)     | по регламенту платформы      | Нужны для таргетинга и статистики           |
| Результаты аукционов | ClickHouse (Auction)   | по регламенту платформы      | Разборы и ML-данные                         |
| Контракты, резервы   | Financial DB           | вместе с финансовой историей | Бухгалтерский учёт                          |
| Задачи с ошибками    | RabbitMQ DLQ           | 14 дней                      | Время на разбор и повторную отправку        |
| Кэши                 | Redis                  | TTL / до пересборки          | Данные восстанавливаются из Kafka и API     |

## Мониторинг потока

| Метрика                       | Что показывает                        | Когда алерт                                                      |
|-------------------------------|---------------------------------------|------------------------------------------------------------------|
| **Consumer lag**              | Сколько событий не обработано в Kafka | Для обновления кэшей и статистики - больше 1 минуты              |
| **Длина очередей RabbitMQ**   | Сколько задач ждёт обработки          | Рост очереди `transaction` или `credit` дольше 30 секунд         |
| **DLQ > 0**                   | Задачи, которые не удалось обработать | Немедленный алерт: деньги и отчёты                               |
| **Отставание репликации ИЛИ** | Применение событий воркерами          | Рост задержки между событием и обновлением кэша больше 30 секунд |
