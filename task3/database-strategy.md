# 4. Выбор базы данных для каждого сервиса

**Принципы:** 
 - у каждого сервиса своё хранилище
 - чужие базы напрямую не читаются - данные получают через API или события
 - Деньги и настройки: PostgreSQL с транзакциями
 - Hot path: Redis в памяти 
 - История и аналитика: ClickHouse 
 - События: Kafka 
 - задачи с повторами: RabbitMQ

| Сервис             | База данных                                   | Что хранит                                                                                                                                               | Обоснование                                                                                                                           | Рассмотренные альтернативы                                                                              |
|--------------------|-----------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| Campaign Service   | PostgreSQL (Primary/Replica)                  | campings, content, strategy                                                                                                                              | Связанные данные со строгими правилами: у кампании есть контент и стратегия ставки. Нужны транзакции и внешние ключи, объём умеренный | NoSQL не гарантирует целостность связей; ClickHouse плохо подходит для частых изменений отдельных строк |
| Financial Service  | PostgreSQL (Primary/Replica, ACID)            | budgets, state_budgets, reserve_budgets, credits, debits, transactions, accounts                                                                         | Деньги: нужны ACID-транзакции, идемпотентность операций и аудит. Именно это указано в описании контейнера                             | База без строгих транзакций рискует потерять или задвоить деньги                                        |
| Analytics Service  | ClickHouse (Primary/Replica, OLAP)            | events, aggregates, reports                                                                                                                              | Аналитика читает миллиарды строк и считает суммы - колоночная база делает это за секунды и хорошо сжимает данные                      | PostgreSQL на таком объёме тормозит и мешает рабочим запросам                                           |
| Bidding Service    | Redis 7 (Primary/Replica, Failover, Sentinel) | campaigns, strategy, content, banners, users_targeting, campaigns_targeting, state_budgets, budgets, reserve_budgets, statistic_budgets, calculated_bids | Аукцион обязан ответить за десятки миллисекунд: данные должны лежать в памяти. Есть атомарные операции для резерва бюджета            | Любая дисковая база в hot path не уложится в бюджет времени                                             |
| Auction Service    | ClickHouse (Primary/Replica, OLAP)            | candidates_data, auction_result, ML_data, rules                                                                                                          | История аукционов - это большой объём записей, который потом только читают для разбора и обучения моделей                             | Операционные базы не рассчитаны на такие объёмы истории                                                 |
| Delivery Service   | PostgreSQL (Primary/Replica)                  | responses, type_url, banners                                                                                                                             | Нужен быстрый поиск дубля по `request_id` и связь баннера с кампанией: это связанные данные с транзакциями                            | Хранить готовую разметку баннера в ClickHouse неудобно - нужны точечные чтения и обновления             |
| Statistics Service | ClickHouse (Primary/Replica, OLAP)            | action_EndUser, users_targeting, campaigns_targeting                                                                                                     | Действия с рекламой - огромный поток записей; агрегаты по ним считаются быстро, запись идёт батчами                                   | PostgreSQL не выдержит поток действий на каждое событие                                                 |
| Advertiser BFF     | Redis 7 (Primary/Replica, Failover, Sentinel) | campaigns, budgets, aggregates, dashboard                                                                                                                | Кэш кабинета: пользователь ждёт страницу сразу, данные должны отдаваться мгновенно                                                    | Дисковые базы дадут заметную задержку на стартовой странице                                             |
| Kafka              | Apache Kafka 3.x                              | Все события платформы                                                                                                                                    | Надёжный журнал: несколько потребителей, повторное чтение, порядок в пределах ключа, гарантия at-least-once                           | Очередь без хранения истории не даст перечитать события после сбоя                                      |
| RabbitMQ           | RabbitMQ                                      | Задачи: credit, callback, transaction, report                                                                                                            | Очередь задач с подтверждением обработки, повторами и DLQ - ровно то, что нужно для платежей и отчётов                                | Kafka не даёт удобных NACK/requeue с задержкой для отдельной задачи                                     |
