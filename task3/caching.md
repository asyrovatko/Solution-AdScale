# Стратегия кеширования

В решении два независимых кластера Redis: **bidCache** (для аукциона) и **bffCache** (для кабинета). 
Они не влияют друг на друга: проблема в одном не задевает другой.

## bidCache — кэш сервиса ставок (hot path)

| Что кэшируем                                                     | Тип данных  | Как обновляется                                                                 | Инвалидация                                              | Прогрев                                       |
|------------------------------------------------------------------|-------------|---------------------------------------------------------------------------------|----------------------------------------------------------|-----------------------------------------------|
| **campaigns**                                                    | исходные    | По событию `campaign_changed` [5.1.1]                                           | Перезапись новой версией из Statistics Service           | `bid_cache_init` при пустом кэше [2.R.2.3(a)] |
| **strategy** (budget_rules, targeting_rules, multipliers)        | исходные    | По событию `strategy_changed` [5.1.1]                                           | Перезапись новой версией из Statistics Service           | `bid_cache_init` при пустом кэше [2.R.2.3(a)] |
| **content**                                                      | исходные    | По событию `content_changed` [5.1.1]                                            | Перезапись новой версией из Campaign Service             | `bid_cache_init` при пустом кэше [2.R.2.3(a)] |
| **banners**                                                      | исходные    | Через Delivery API по событию `adContent_changed` [5.1.1.1]                     | Новый баннер заменяет старый                             | Запрашивается при обновлении контента         |
| **users_targeting**                                              | исходные    | По событию `user_targeting_changed` [5.1.2]                                     | Перезапись из Statistics Service                         | `bid_cache_init` при пустом кэше [2.R.2.3(a)] |
| **campaigns_targeting**                                          | исходные    | По событию `campaigns_targeting_changed` [5.1.2]                                | Перезапись из Statistics Service                         | `bid_cache_init` при пустом кэше [2.R.2.3(a)] |
| **state_budgets** (budgets, reserve_budgets, statistic_budgets)  | исходные    | По событию `state_budget_changed` [5.1.3]                                       | Перезапись из Financial Service                          | `bid_cache_init` при пустом кэше [2.R.2.3(a)] |
| **budgets**                                                      | производная | Вычисляется воркером [5.1.4.1]                                                  | Пересчёт при обновлении исходных                         | Пересчёт после записи исходных                |
| **reserve_budgets**                                              | производная | Вычисляется воркером [5.1.4.1] / Создаётся перед формированием конракта [2.R.4] | Пересчёт при обновлении исходных / Возврат при проигрыше | Пересчёт после записи исходных                |
| **statistic_budgets**                                            | производная | Вычисляется воркером [5.1.4.1]                                                  | Пересчёт при обновлении исходных                         | Пересчёт после записи исходных                |
| **calculated_bids**                                              | производная | Вычисляется воркером [5.1.4.1]                                                  | Пересчёт при изменении cnhfntubq/таргетинга/бюджета      | Пересчёт после записи исходных                |

## bffCache — кэш кабинета рекламодателя

| Что кэшируем   | Тип данных   | Как обновляется                                                           | Инвалидация                                     | Прогрев                                     |
|----------------|--------------|---------------------------------------------------------------------------|-------------------------------------------------|---------------------------------------------|
| **campaigns**  | исходные     | Событие `campaign_changed` [5.2.1] или REST-запрос `GET campaign` [1.4.1] | Сброс после действий пользователя и по событию  | При промахе параллельные запросы к сервисам |
| **budgets**    | исходные     | Событие `state_budget_changed` [5.2.2] или `GET budgets` [1.4.3]          | Сброс после действий пользователя и по событию  | При промахе параллельные запросы к сервисам |
| **aggregates** | исходные     | Событие `analytics_changed` [5.2.3] или `GET aggregates` [1.4.2]          | Сброс после действий пользователя и по событию  | При промахе параллельные запросы к сервисам |
| **dashboard**  | производная  | Вычисляется BFF [5.2.4.1] после обновления исходных                       | Пересчёт при обновлении любой из составляющих   | Собирается при первом запросе кабинета      |

## 6.3. Защита от типичных проблем кэша

| Проблема                       | Что это                                                                               | Как защищаемся в решении                                                                                                            |
|--------------------------------|---------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| **Лавина промахов**            | Популярная запись исчезла, и множество запросов одновременно идёт к сервису-владельцу | Параллельные запросы ограничены тайм-аутом 2 с [1.4.1–1.4.3]; при пустом кэше ставок запускается один `bid_cache_init` [2.R.2.3(a)] |
| **Устаревшие данные**          | Кампания изменилась, а в кэше старая версия                                           | Обновление по событию с сравнением версии; кэш ставок обновляется в пределах времени применения события                             |
| **Потеря кэша ставок**         | Redis недоступен или кэш пуст                                                         | Сервис отвечает `cache_empty` и инициирует инициализацию; до её завершения отвечает `no-bid`, а не ошибкой [2.R.2]                  |
| **Отказ Redis**                | Кластер недоступен                                                                    | Redis 7 с Failover и Sentinel: реплика подхватывает роль основной                                                                   |
| **Рост нагрузки на источники** | Частые события вызывают частые обращения                                              | Батчевое накопление в статистике [3.S.3] и пересчёт производных внутри воркера, без обращений к сервисам                            |
