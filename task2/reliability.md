## Паттерны надежности

**Термины простыми словами:**
- **Предохранитель (circuit breaker)** - если сервис часто ошибается, временно перестаём к нему обращаться и сразу отвечаем запасным вариантом.
- **Повтор с задержкой (backoff)** - повторяем через 1 с, затем 2, 4, 8… чтобы не добить больной сервис.
- **Идемпотентность** - повтор операции не меняет результат: деньги не спишутся дважды.
- **Резервный ответ (fallback)** - что отдаём, если зависимость недоступна.

### Защита на каждом уровне

| Уровень         | Механизм                                         | Где в схеме           |
|-----------------|--------------------------------------------------|-----------------------|
| Внешний трафик  | Ограничение частоты, авторизация, предохранитель | API Gateway (`2.R.1`) |
| Между сервисами | mTLS, sidecar, тайм-ауты                         | Istio Sidecar         |
| Кабинет         | Тайм-аут 2 с, 2 повтора, CB 50 %/30 с            | BFF (`1.4.1`-`1.4.3`) |
| Аукцион         | Бюджет 80 мс и отказ вместо ошибки               | Bidding Service       |
| Деньги          | Идемпотентность, saga, DLQ, сверка               | Financial Service     |
| Данные          | Реплики, Failover, Sentinel                      | PostgreSQL и Redis    |
| События         | Повторы, DLQ, отставание потребителей            | Kafka и RabbitMQ      |

> **Главное правило hot path:** в аукционе **повторов нет** — есть только бюджет 80 мс и отказ (no-bid). Повторы применяем там, где можно подождать: обновление кэша, действия, деньги, отчёты.

| Сервис (кто -> кого)                                                   | Предохранитель                         | Повторы                                                                             | Идемпотентность                                           | Резервный ответ                                                                             |

| **Ad API -> Ad Server**                                                | Внутри сервиса                         | Нет                                                                                 | Да, повтор даёт тот же результат                          | no-bid отказ вместо ошибки                                                                  |

| **Ad Server -> Auction Service**                                       | Да, по направлению gRPC (`2.R.3`)      | Нет                                                                                 | Да, по контексту аукциона                                 | Аукцион не проведён: ветка "создать резерв бюджета кандидата" (`2.R.4`) либо no-bid         |

### Стандартные настройки повторов

| Параметр                           | Значение                                               |
|------------------------------------|--------------------------------------------------------|
| Начальная задержка в очереди задач | 1 с                                                    |
| Множитель                          | × 2 (1 с -> 2 -> 4 -> 8)                               |
| Что повторяем                      | Тайм-ауты, временные ошибки, недоступность базы        |
| Что **не** повторяем               | Ошибки валидации, бизнес-ошибки: повтор их не исправит |
| Предел попыток в RabbitMQ          | 3, затем DLQ                                           |
| Предел попыток отчётов             | 3, затем DLQ                                           |
| Повторы в hot path                 | Не применяются                                         |

### Что должно настораживать дежурного

| Сигнал                                | Что означает                                       | Первое действие                                  |
|---------------------------------------|----------------------------------------------------|--------------------------------------------------|
| Растёт доля no-bid из-за пустого кэша | Кэш ставок не наполнился или сбросился             | Проверить `bid_cache_init` и Update Cache Worker |
| Разомкнулся предохранитель            | Сервис-получатель недоступен или медленный         | Посмотреть трассировки и метрики сервиса         |
| Растёт DLQ                            | Задачи не обрабатываются: ошибка данных или логики | Разобрать сообщения, исправить и повторить       |
| Отставание потребителей Kafka         | Воркеры не успевают                                | Проверить нагрузку и число потребителей          |
| Расхождение резервов и списаний       | Контракт не дошёл до Financial                     | Сверить резервы в кэше с базой финансов          |
