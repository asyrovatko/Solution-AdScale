### Обоснование протоколов

| Протокол                 | Почему выбран                                                                                                                                                                                                                                     |
|--------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **gRPC over mTLS**       | Вызовы, где ответ нужен немедленно: горячий путь и запросы таргетинга. Бинарный формат компактнее JSON, одно соединение несёт много запросов, срок ответа передаётся по цепочке. Контракт строго описан, сервисы не расходятся по формату данных. |
| **HTTPS/REST over mTLS** | Внешние и административные вызовы: кабинет рекламодателя, финансы, аналитика. Понятный стандарт, легко отлаживать, работает через любые прокси.                                                                                                   |
| **Kafka**                | События, которые не влияют на ответ пользователю прямо сейчас: изменения кампаний, действия, бюджет, аналитика. Отправитель не ждёт получателя, событие хранится и читается несколькими сервисами независимо.                                     |
| **RabbitMQ**             | Задачи, которые обязаны выполниться: платежи, формирование отчётов. Есть подтверждение обработки, повтор с нарастающей задержкой и очередь для разбора неудачных задач.                                                                           |
| **Redis (RESP3)**        | Горячие данные аукциона и кабинета. Ответ за доли миллисекунды, атомарные операции не позволяют двум аукционам истратить один и тот же рубль бюджета.  Запись идёт в primary, чтение - на replica.                                                |
| **JDBC (PostgreSQL)**    | Транзакции с гарантией (ACID): деньги, настройки кампаний, ответы по показам. Запись идёт в primary, чтение - на replica.                                                                                                                         |
| **ClickHouse (батчами)** | Аналитика: события, агрегаты, отчёты. Пишется пачками, а не по одной строке. Быстрые агрегаты. Запись идёт в primary, чтение - на replica.                                                                                                        |
| **OTLP / Prometheus**    | Наблюдаемость: метрики, трассировки, логи. Единый стек на все сервисы.                                                                                                                                                                            |
